## 一、标准版（推荐）

**基于多模态大模型的智能导盲辅助系统（"光引" Lumina）** ｜ 独立开发 ｜ 2025.09 - 2026.01
**技术栈：** Python / PyTorch / Ultralytics YOLOv11n / ONNX Runtime / RapidOCR / Qwen3-VL / Edge-TTS / Flask-SocketIO / 高德地图 API / ESP32-S3

- 设计并实现**端云协同**的视障辅助系统：本地 YOLOv11n（ONNX 加速）以 320×320 推理、跳帧调度实现 **20+ FPS** 的实时避障；云端接入 **Qwen3-VL-8B** 多模态大模型，通过线程异步 + 回调实现**不阻塞主视频流**的场景理解与视觉问答。
- 融合"检测 / 分割 / OCR / VLM"四种感知能力：定制盲道与斑马线**语义分割模型**，用**质心法 + 三分区域**判定算法输出"向左平移 / 向右微调 / 直行"等盲道循迹指令；集成 **RapidOCR(ONNX)** 实现药盒、路牌、书本文本一键朗读，并设计**黑名单 + 纯数字过滤**剔除画面 UI 文字误识别。
- 基于**透视投影**的单目风险评估模型（CRAM）替代绝对测距：以检测框面积占比 + 类别危险指数计算风险值，红绿灯引入 **HSV 色相掩码投票**识别红/黄/绿三态，并结合路口状态机区分"普通行走 / 临近路口"两种红绿灯策略。
- 实现**动态优先级语音调度器**：基于 `PriorityQueue` + Edge-TTS 神经语音（zh-CN-YunxiNeural，语速 +35%），P0 危险警报可**打断清空**低优先级播报，并以 **MD5 文本哈希缓存**音频文件实现毫秒级重复播报。
- 开发"宏观 GIS + 微观视觉"双尺度导航：调用高德 `direction/walking` / `direction/transit/integrated` 规划路线，自主实现**折线投影吸附算法 + Haversine 距离 + 真北方位角**，支持偏航自动重规划、路口预判与"时钟方位"语音播报（"向您的 2 点钟方向"）。
- 设计 **GPS 精度加权滑动窗口滤波 + PDR 步态推算融合**：按精度与时间双权重平滑 GPS、剔除跳点，用手机 IMU 步频（0.6 m/步）高频推算位置，解决 GPS 低频漂移导致的导航失步问题。
- 搭建 Flask + SocketIO 远程监护平台：JPEG(base64) 低延迟视频图传、10×10 风险热力图、出行日志与预警时间序列、**手机端 GPS 上报与远程语音干预/SOS 告警**，全链路 HTTPS 自签证书以支持浏览器高精度定位。

## 二、详细版（适合投 AI/CV 岗，项目单独占一块版面）

**基于多模态大模型的智能导盲辅助系统（"光引" Lumina）** ｜ 核心开发 ｜ 2025.09 - 2026.01
**技术栈：** YOLOv11n、ONNX Runtime、PyTorch、RapidOCR、Qwen3-VL-8B、SenseVoice ASR、Edge-TTS、Flask / Flask-SocketIO / Flask-Login / SQLAlchemy、高德开放平台 API、ESP32-S3 + OV2640

- **感知层**：以 YOLOv11n 为主干检测 80 类 COCO 目标，筛选行人/自行车/汽车/摩托车/公交车/卡车/红绿灯 7 类危险目标；实现 `.pt → .onnx` 自动降级加载（存在 ONNX 权重则走 ONNX Runtime，否则 PyTorch），保证 CPU 环境下推理延迟 < 40 ms。
- **决策层**：自研盲道语义分割循迹算法（掩码质心 + 上下三分区 + 安全区阈值 ±16.5% 宽度 + 转向容差 15%），将"盲道在哪"转译为"人往哪走"的听觉指令；融合检测框面积比（>10% 触发绕行、>30% 触发碰撞预警）与掩膜缓存策略（分割每 3 帧执行一次）。
- **认知层**：封装 Qwen3-VL-8B（SiliconFlow OpenAI 兼容接口）场景描述与视觉问答，系统提示词约束输出 ≤25 字口语化中文；采用独立守护线程 + 回调函数，避免 2~3 s 的推理阻塞 20 FPS 的检测主循环。
- **交互层**：设计按键/语音双通道（`T` 朗读文字、`D` 场景描述、`V` 语音指令、`Q` 退出），语音链路为 `SpeechRecognition` 采集 → SenseVoiceSmall 云端转写 → 规则化意图分类（NAV / NAV_FLEX / NAV_CONTROL / QUERY_LOCATION / CHAT）。
- **导航层**：实现"宏观路线 + 微观避障"优先级仲裁（视觉警报 > 地图指引），路口通过 `is_approaching_intersection` 状态位与红绿灯检测联动，绿灯时额外校验斑马线区域（下半画面）是否有车/人阻挡。
- **监护层**：Flask-SocketIO 采用 `threading` 异步模式规避与 `pygame`/`asyncio` 的事件循环冲突；实现用户/监护人双角色鉴权（Flask-Login）、SQLite 出行日志、快照留存、灵敏度远程调节与 SOS 广播。

## 四、面试官可能盯的技术关键词（自查是否写得出原理）

| 简历里的词 | 必须能讲清楚 |
| --- | --- |
| 端云协同 | 为什么本地跑小模型、云端跑大模型，边界怎么划（时延 vs 认知能力） |
| 20+ FPS | 怎么测的、瓶颈在哪、做了哪些优化（跳帧、320 输入、ONNX、分割降频） |
| CRAM 风险模型 | 为什么用面积占比代替测距、透视原理、单目缺陷与补救 |
| HSV 色相投票 | 为什么不用 RGB、OpenCV H 的 0~179 范围、红色双区间处理 |
| 质心法循迹 | 为什么取下三分之一而不是全图、三分区域的意义 |
| 优先级队列 TTS | 为什么"清空队列 + 停播"而不是排队等待、如何避免播报轰炸 |
| MD5 音频缓存 | 缓存 key 设计、命中率收益、磁盘清理策略（可讲改进方向） |
| 折线投影吸附 | 点到线段投影公式、为什么限制 t∈[0,1]、与 map-matching 的关系 |
| 时钟方位播报 | 真北方位角 → 相对角 → 12 扇区，为什么比"向左转"更适合视障用户 |
| GPS 精度加权滤波 | 为什么纯时间加权不够、跳点如何检测（速度阈值 150 km/h） |
| PDR 步长 0.6 m | 误差来源、为什么必须用 GPS 做锚点定期校正 |
| HTTPS 自签证书 | 为什么手机浏览器 GPS 需要安全上下文（secure context） |

## 五、简历撰写提醒（避免翻车）

1. **不要写"已量产 / 已落地"，写"完成原型系统并通过 XX 场景实测"**。项目是竞赛 + 研究原型阶段，面试官追问部署规模时如实说明。
2. **不要写"训练了专用数据集"而说不出数据量**。若面试问及，如实回答：使用公开数据集 + COCO 预训练权重做迁移与场景微调，并说明盲道分割的数据来源与标注方式。
3. **密钥问题要主动提**：`config.py` / `web/app.py` 中 API Key 为明文硬编码，面试时主动说明"生产环境应迁移到环境变量 / 密钥管理服务并做 .gitignore 隔离"，这是加分项而非减分项。
4. **性能数字要给出测试环境**：CPU 型号（i5-12500H）、输入分辨率 320×320、YOLO 推理延迟 <40 ms，端到端 FPS 20+，便于面试官复现口径。
5. **"多模态大模型"标题与内容要对齐**：项目确实调用了 Qwen3-VL（视觉+文本）与 SenseVoice（音频+文本），可放心写"多模态"；不要声称"自研或微调了大模型"，是 API 调用 + 提示工程。
